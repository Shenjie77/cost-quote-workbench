# v0.6.0 · 成本版本锁定与独立 DRB 流程

## 更新内容

- 成本锁只锁定对应版本。已定稿或已有历史 DRB 锁定的版本保持成本不可修改，项目仍可新建空白 Draft，或复制锁定版本重新估算。锁定版本可正常查看多维度汇总、版本对比和导出。
- 进入、提交或完成 DRB 前，必须先明确确认对应成本为 **Confirmed**。页面弹窗展示项目、版本、计算后的总成本和人天；取消不修改成本或流程。确认窗口打开后若成本或评审资料发生变化，会要求重新核对。成本确认本身不代表 DRB 已批准。
- 每个成本版本有独立的 DTRB / DRB 流程与评审依据。新建 Draft 自动成为活动版本，并开启该版本的 DTRB 流程；旧版审批不能替代新版评审。查看历史成本不会改变当前工作流程所属版本。
- 修正历史 Draft 的 DRB 待办：登记通过、附条件通过或关闭条件前，同样需要先确认该版本的成本。历史成本与实际审批记录保留，新的流程操作由服务端统一校验。
- CLI 与业务 Skill 同步更新：`cost create` 自动选中新 Draft；`cost get --version Vn --section workflow` 可局部读取指定版本的流程；`ssr submit --version Vn` 可明确指定送审版本，省略时使用当前流程版本 `workflowVersion`。相关返回值包含流程版本和目标版本信息，无需读取整个 workspace。
- Master Data Resources 仍可维护；成本锁保护该版本的成本输入及已捕获费率。主数据更新不会重新计算已锁定版本。

## 验证

已通过 **171 项自动测试**、Lint、TypeScript 类型检查和生产构建。覆盖版本成本保护、新 Draft 流程、DRB 确认与取消、历史评审、CLI 版本定位、并发保存和迁移兼容。

## 安装与升级

需要 Node.js **22.18.0 或更新版本**。提供源码 ZIP 与 SHA-256 校验文件；ZIP 中的 19 个项目级 Skill 入口展开为普通目录，Git 仓库中保留链接。

已有安装先运行 `npm run backup:local`，再停止旧服务。Git 用户在工作区干净时运行 `git pull --ff-only`；ZIP 用户解压到新目录，在旧服务停止后保留原安装的完整 `data/`、所需 `outputs/` 和本地配置。

```sh
npm ci
npm run build
npm start
```

访问 `http://localhost:3000/`。已有项目无需重新 seed。

数据库升级到 **schema 5**，支持从公开 v0.5.0 的 schema 3 直接升级，并包含按版本成本锁的兼容迁移。首次启动自动迁移一次，保留原始文档归档：现有最高 Draft 的当前流程回到 DTRB，原进度保存在历史流程归档中；成本快照、历史锁及实际审批证据继续保留，不会自动把 Draft 确认为 Confirmed。之后由用户核对成本再推进本版本 DRB。若需回退程序，应使用升级前的数据库备份。

本版 `cost create` 会改变活动版本，调用方应使用返回的新版本号和 revision 继续更新；这是相对 v0.5.0 的行为调整。客户报价及模板填充仍需核对所选成本版本。Skill 列表未刷新时重新打开项目任务。
