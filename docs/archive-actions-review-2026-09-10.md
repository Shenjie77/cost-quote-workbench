# 项目文档入口与流程目录策略：修改及验证记录

## 完成的修改

- Project Files & Archive 和步骤 Documents 中，每个文档的 Download 旁增加 Open Folder、Delete。删除前确认文件名，成功后同步刷新相关列表；失败时保留记录并显示错误。
- Project Archive Folder、项目实际归档目录及项目编辑中的目录增加打开入口。入口使用已保存的路径，文档入口打开该文件实际所在的目录。
- Workflow 模板的每个 Step 增加 Create Folder，默认开启。项目创建时保存目录策略；之后修改模板开关不补建、删除或迁移旧项目的节点目录。
- 未设置独立文件夹的步骤将文档存入项目 workflow 目录，仍保留步骤、轮次和文件元数据，查询与下载保持可用。
- 文件删除加入恢复副本、校验、事务和删除回执。失败与中断场景保留可恢复内容，重复删除和旧上传请求重试不会重建已删除文档。
- 为新增接口、目录策略和删除恢复逻辑补充职责及关键分支注释；目录打开和文件删除分别封装为独立服务。

## 自检发现与修正

1. 旧目录映射为空时，不能依据今天的流程模板补建目录；改为保存空策略并增加旧数据库回归测试。
2. 文件恢复与目录同步共用 SQLite 事务时出现嵌套事务冲突；明确事务归属，并验证并发、外层事务及归档迁移冲突。
3. 仅切换 Create Folder 时，流程预览会因对象属性顺序产生误报；使用稳定内容比较，并保留旧项目的目录选择。
4. 全量测试发现 CLI workspace.list 的独立响应契约遗漏 createFolder；补齐可选布尔字段，并验证默认开启和关闭值。

## 使用说明

Open Folder 打开的是运行工作台本地 API 的电脑上的目录。Windows 使用 Explorer，macOS 使用 Finder，Linux 使用系统桌面文件管理器。
