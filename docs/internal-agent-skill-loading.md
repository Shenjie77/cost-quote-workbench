# 内部模型如何减少技能加载

## 已完成的仓库改动

22 个 SKILL.md 全文均不超过 300 字符，包括 YAML 名称、描述、标点、空格及换行。
详细步骤保留在各技能 `references/guide.md`；原有版本锁、revision、用户确认及历史快照规则保留。
简单成本/流程查询可直接执行短入口中的命令；写入、导出先读取所选技能的操作说明。
`node scripts/check-business-skills.mjs` 会拦截超长入口、失效引用及过期索引。

这只减少提供给模型的内容。内部平台若仍每次递归读取全部参考文件，耗时不会因此消失。
本次未连接或修改公司内部模型的加载服务。

## 建议的加载方式

1. 内部模型初始上下文仅附 [skills/index.md](../skills/index.md)，或直接使用各技能的 name/description 元数据，二选一，不重复附加。
2. 依据用户意图选择一个名称，从 `skills/<名称>/SKILL.md` 读取短入口。校验名称属于索引，不接受模型构造任意文件路径。
3. 普通查询可直接执行；写入/导出读取该入口明确要求的 guide。只有本次操作涉及导入、模板等情形时再读对应参考文件，不预读其他技能。
4. 同一会话已提供且仍保留在上下文中的文件不重复读取或附加。跨会话由宿主按权限、仓库版本和文件路径缓存文件内容；部署更新时失效。上下文已压缩丢失必要规则时按需重载。

文件缓存减少文件读取；把同一份大文本再次发给模型仍有处理开销。模型服务的 prompt cache 是否可用、如何计费和生效需由内部服务另行确认，不等同于宿主文件缓存。不要缓存成本查询结果代替实时查询。

## 简单查询可以完全不加载技能正文

如果内部平台支持固定工具，可直接提供 `query_project_cost(project_id, version?)`，由服务端适配以下已有 CLI：

```sh
node cli/cost-cli.mjs cost get --project-id ID --section summary
```

有版本才加 `--version Vn`，未指定则使用活动版；以参数数组启动进程，不拼接 shell 字符串。
名称匹配使用已有 `project list`；多匹配让用户选择，不随意挑选。
返回项目 ID、版本、币种、revision 和 `data.value`；`totalWithRisk` 为含风险总成本，不能再次叠加子项或 3%。
保持原命令错误与权限边界，不自动写入、导出或改成本状态。

这是供内部平台实施的工具适配方案，仓库本次没有新增同名 CLI 命令或对外服务。
复杂写入继续按对应 guide 执行；不要为了省加载而跳过业务约束。

## 验收记录

分别记录技能文件读取数量/时间、附加文本量、模型处理时间、CLI 执行时间和总时间。

- 已知项目 ID 查成本：按需方案读取 1 个短入口、0 个参考文件、调用 1 次成本汇总。
- 固定查询工具方案：读取 0 个技能正文，调用 1 次成本汇总。
- 更新成本：读取 1 个短入口、其操作说明，以及此次变更需要的细则；不加载全部 22 个技能。
- 更新仓库后重复同一任务：宿主使用新版本缓存，不继续提供旧技能规则。

实际 60–90 秒能降低多少需内部模型实测；本地字符数或 CLI 执行时间不能替代端到端结果。
