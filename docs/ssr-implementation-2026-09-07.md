## 核心约束

- 后续补充：DRB 通过并关闭条件、显式完成 DRB/成本基线节点，或成本版本 `Confirmed`，都会锁定项目成本及 RE 费率。锁定后仅允许把不变的 Draft/Suspended 成本标记为 Confirmed 以继续报价，不允许改价或降级绕过。送审与配置归档保留独立快照。
- CPQ 首先接受简述并推荐现有编码，不要求 TD 提供详细 scope 或每项成本。人工选择确认后才计算；固定设备数量不能由成本反推。
- 多服务配量优先使用可解释的参考。没有参考时，等额预算是明确的计算假设，不代表 TD 实际投入。搜索达到上限不等于无解。
- 新 CPQ 结果在保存时核对固定数量和金额；归档核对当前成本和目录快照，旧档案不受目录后续改价影响。
- 金额与单位精度明确，不能修改固定数量来掩盖残差；不可满足容差的配置保留草稿。
- 同名评审条件再次出现，需要针对新结果重新关闭。普通提醒的已阅状态不等于公司评审已关闭。
- 对外报价不会自动加入内部成本/费率/利润率来源页，原模板报价也禁止映射内部成本字段。模板里原来已有的内容仍需按实际公司文件复核。

## 使用顺序

1. 建立/打开项目，维护 RE Type、费率及 TD 日期。
2. 在成本工作区导入 TD/PM Excel，检查预览与来源后保存整合成本。
3. 在 SSR 流程填写 Proposal、范围与材料版本、公司记录地址和必需专业领域；登记实际公司送审与结果。
4. 在 CPQ 录入公司目录，输入简短范围，确认候选及固定数量，说明目标成本和分配依据后求解、归档。
5. 报价页面选择模板、价格及法务条款；启用 SSR 的项目需记录适用于当前数据的报价决策才能导出。
6. 原公司 Excel 模板使用 CLI 映射。维护 BOQ 可先生成明确标记的维保报价草稿，正式对外输出走已确认的报价流程。

详细命令和 JSON 示例见 [Skill 操作参考](../skills/cost-workbench/references/operations.md)。`.agents/skills/cost-workbench` 指向同一份项目 Skill，未安装到全局目录。

测试覆盖导入与来源去重、直接人天、CPQ 固定数量与归档、SSR 依赖/条件/撤回/价格条款变化、提醒持久化、BOQ 单台年价、模板布局/条款/缓存、内部成本隔离及真实 CLI 导出历史保存。另在临时数据库按 Skill 完成了一次人工已确认的 CPQ 配置、归档与 Excel 回读，未修改真实项目数据。

仍需要真实资料才能完成的接入验收：

- 尚未提供公司的真实 TD/PM/DRB/报价模板和 CPQ 目录；目前验证使用合成 Excel。必须按实际文件配置映射、排除合计行并在 Excel 重算原模板公式。
- 没有公司平台 API、账号或专用连接。公司审批/CPQ 正式写入仍由公司平台完成，本地保存可核对的记录与链接。不会把登记副本称为已在公司平台提交。
- 提醒仅在本地服务运行时扫描；重启会补查。没有部署系统级常驻服务，也没有自动向 PM 发送消息。
- 内置候选与历史搜索是本地关键词检索。Skill 可以基于真实目录解释和排序；没有部署独立嵌入模型/模型服务，也不会假称已进行语义向量搜索。
- 原模板适配入口和历史 scope 检索目前通过 CLI/Skill 使用；没有额外的可视化模板设计器。
- 维保当前输出为未计税、未完成最终 T&C 的草稿；历史成本比例换算是参考估算，需核实 SLA、期限和实际交付成本。
