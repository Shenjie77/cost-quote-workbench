## 结论

02 版是部分业务的交互样例，并非全站等价实现。年度增幅缺失确实反映了功能盘点不完整。主要问题不只有缺少输入框，还包括用简化表格替代原有业务过程：CPQ 没有约束求解、分包没有年度及站型、维保没有正式年度分摊、文件列表没有操作入口。

本轮补齐可以在独立样例中验证的关键交互，同时把未迁移部分明确列为验收阻塞项。**不能把新增导航、空历史表或禁用按钮算作正式功能已完成。** 37 项是业务能力范围，不是 37 项全部通过的声明。

## 完整页面组织与接入验收

以下是全站目标交互结构。原站仍提供这些完整业务，审核版没有实现的部分必须在正式替换前补齐：

1. **全局工作空间**：一个项目选择器及可横向滚动的已打开项目栏；检索名称、编号、标签和流程。切换后保持当前工作页；成本、报价、版本、草稿必须隔离。保存状态统一显示未保存、保存中、成功、离线及冲突；冲突提供备份/重载，不能静默覆盖。
2. **今日/提醒**：由同一流程计划计算待办、并行节点和 SLA；项目挂起不再提醒，结束轮次停止提醒。Agent 收件箱和本地模型实验必须保留入口；本地 AI 不能写成本或推断公司批准。
3. **项目与流程**：资料原位维护；节点选择后就近展开负责人、跟进日、必填信息、实际开始/截止、原因和附件。操作保留开始、完成确认、跳过、暂停、恢复、重开和项目挂起。前置关键节点、并行、Confirmed 成本门禁、工作日历和历史全部沿用 `workflow-engine.ts`。不能用随意改变下拉状态代替执行引擎。
4. **成本**：版本和目录在公共上下文栏；紧接交付/费率；Y1–Y5、Sites/MD、Group、列设置、Bulk/Import 与表格贴近。组重命名/合并、复制、行排序、列顺序与可见性必须保留。Bulk 在页面内展开，先校验后应用，保留未列行和 ID；关闭后恢复页面滚动。TD/PM 文件映射仍是独立流程。
5. **分包**：采用当前源码的 Overview / 站型 / Shared 结构，不能照旧文档恢复已移除的模式选择器。基准价和参考价要区分；未定价 `null` 不能当作 0。保留旧手工分包、整数 pcs 校验、SGD 限制、公式草稿的 Done/Apply 分离和过期基准保护。
6. **报价**：原站以逐行 GP/单价和显式刷新为主；新生成行默认45%。Single/Scope/Group/Item/Custom、成本权重、报价占比及互斥锁必须全部保留，不能用“每 Category 一个价格”替代。Section 与 Category 是独立字段；折扣说明随各折扣组保存。命名模板、假设库、客户条款、有效期、内部 Remark 和历史仍是必需内容。
7. **客户输出**：原源码支持合法 Draft 输出，Final 才要求 Confirmed 成本及适用报价决策；两者都不能绕过金额错误。普通报价、客户工作簿映射、服务+维保组合、Quotation + Simple Cost、原件归档和历史快照都须验收。报价 Excel 当前保存至归档目录，不应重新设计成无条件双重下载。内部商业总额、客户 Section 合计和历史金额以当前 `customer-document.ts`/分组规则核对，不能只凭旧文档的 Optional 描述推断。
8. **CPQ**：映射确认与结果有效性是两个状态；目录/选择变化须重新确认，成本基准变化须重算。不可把求解金额当作客户报价。正式归档必须通过容差和新鲜度校验并捕获成本版本/Proposal。
9. **维保**：保留独立 MV 版本、BOQ导入/批量、型号/服务等级/站点历史对照、年度金额和归档。CT/SPMS、数量、年限直接编辑；历史价格只供对比，不能自动作为成本或推荐售价。
10. **文件**：根目录只影响新项目；当前项目路径另行迁移，保留未登记文件，复制和校验成功才提交。文件可在成本锁定/流程完成后补充；不能因此解锁或推进流程。按类别/节点/版本查询，上传队列、失败重试、下载、打开所在目录和删除确认均须保留。
11. **测算草稿**：必须保留 Univer 公式、多工作表、数据库修订和离线恢复、JSON 备份；当前审核版的数量×单价表不具备这些能力，不能替代。
12. **主数据**：12类导航完整不等于12类编辑器完整。每页独立revision保存、校验、导入/导出及冲突处理都应接入原模块。资源、CPQ、分包、假设和模板显式采用到项目，不能维护目录时追溯改写旧版。

## 上线阻塞项

真实项目隔离、自动保存/冲突、工作流完整执行、报价完整逐行编辑及模板导出、Bulk/Import、Univer草稿、CPQ/维保历史归档、全局主数据完整维护和本机文件接口仍未接入审核版。它们在功能对照页标为部分覆盖或待迁移，继续由旧平台提供。暂不替换默认生产入口。

客户仍按 Git 拉取、本机运行的方式升级。保留当前数据模型、API、SQLite、实际归档路径和历史；见 `docs/local-upgrade.md`。正式切换前必须在真实数据的副本上走完上述流程，不用演示数据做迁移输入。
